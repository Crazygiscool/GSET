# GSET Windows installers

This directory holds the two Windows installers produced at release time:

| File       | Format | Scope                                     |
| ---------- | ------ | ----------------------------------------- |
| `gset.nsi` | EXE (NSIS 3) | "Install for all users" (per-machine, default) or "Install just for me" (per-user), selectable at install time |
| `gset.wxs` | MSI (WiX Toolset v4/v5) | per-machine only |

Both install `gset.exe` and add its directory to `PATH` (system PATH for
per-machine, user PATH for per-user) so `gset` works from any new console.

`gset.ico` is a placeholder icon generated by hand (a 256x256 PNG in an ICO
container, no image tooling required). Swap it for a real brand icon before the
first public release if you like.

## Building the EXE installer

Requires [NSIS 3](https://nsis.sourceforge.io/) (the standard installer ships
`MUI2.nsh`, `LogicLib.nsh`, `FileFunc.nsh`, `nsDialogs.nsh`, and `StrFunc.nsh`,
which this script uses).

The script reads everything from defines, stamped per release:

```bat
makensis -DVERSION=3.3.0 -DBINARY=C:\path\to\gset.exe -DLICENSE=C:\path\to\LICENSE ^
         -DICON=C:\path\to\packages\windows\gset.ico ^
         -DOUT=C:\out\gset-3.3.0-windows-amd64-setup.exe packages\windows\gset.nsi
```

Every define has a default, so `makensis packages\windows\gset.nsi` also works
unmodified if `gset.exe` and `LICENSE` sit next to the script (the default
output is `gset-<VERSION>-setup.exe`). NSIS accepts the `-D` form everywhere;
`/D` is the Windows-only spelling.

## Building the MSI installer

Requires the WiX Toolset, installed as a .NET global tool (needs a .NET SDK).
Pin v5 - since v7, WiX requires accepting its OSMF (Open Source Maintenance Fee)
EULA, and this project's `.wxs` is v4/v5 schema:

```bat
dotnet tool install --global wix --version 5.0.2
wix build packages\windows\gset.wxs ^
       -d Version=3.3.0 ^
       -d Binary=C:\path\to\gset.exe ^
       -d License=C:\path\to\LICENSE ^
       -d Icon=C:\path\to\packages\windows\gset.ico ^
       -o C:\out\gset-3.3.0-windows-amd64.msi
```

The MSI is per-machine (needs elevation to install), embeds an
Add/Remove Programs entry and a "GSET Command Prompt" start-menu shortcut, and
replaces older versions in place via `MajorUpgrade`.

## Local validation

`packages/windows/check-installers.sh` compile-checks both sources without a
Windows machine, so regressions surface on every push instead of at
release-tag time (it runs as the `windows-installers` job in `test.yml`):

```bash
packages/windows/check-installers.sh   # needs "nsis" (makensis) and python3
```

It compiles `gset.nsi` with a stub `gset.exe` payload and verifies `gset.wxs`
is well-formed XML. (WiX's full schema validation still requires the `wix`
tool on a .NET host.)

## What CI does

`.github/workflows/release.yml` builds both installers on `v*` tag pushes and
also smoke-tests them on `windows-latest`: silent EXE install `/S /ALLUSERS`
then silent uninstall, and `msiexec /i ... /qn` then `msiexec /x ... /qn`,
checking the binary appears in Program Files and that the system `PATH`
gains (and later loses) the `GSET` entry.
